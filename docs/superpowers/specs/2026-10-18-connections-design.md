# Citizen connection requests

The owner requests a send-connection feature and supplies a social-network reference image. Build the connection flow, retaining Namma Civic's existing theme and anonymous Citizen labels. The default scope is all citizens through a People page; the owner can narrow it to leaders. Chat, stories, followers and personal-name profiles are outside this request.

People discovery is opt-in and ward based. An anonymous profile contains a ward and optional PII-scrubbed bio only, never a name, contact detail, precise location, avatar identity or raw UID. Public discovery returns only enabled profiles. A sender must enable their own profile, and the recipient must be discoverable before a new request can be created. Existing requests/connections remain visible only to participants after discovery is disabled.

Add a People page with region selector, searchable Citizen cards, Connect/Requested/Connected controls, Incoming/Sent/Connections tabs, accept/decline/cancel/remove actions, profile discovery controls, loading/error/empty states and explicit confirmations for removal. Preserve the warm/serif/clay theme and reduced-motion support. Link opt-in creator profiles from the leader directory; do not expose a connection identity for a citizen who has not opted in for that ward.

Use authenticated API writes, private server-only profile/connection collections and one transaction per unordered pair. Repeated send/response clicks are idempotent; simultaneous opposite requests must not auto-connect. Only the recipient can accept/decline, only the sender can cancel, and either participant can remove an accepted connection. Reject self-requests, nonparticipants, undiscoverable targets and stale action revisions. New sends are bounded by a server rate limit. A decline/removal imposes a 24-hour cooldown in both directions so reversing/cancelling cannot bypass it. Each new pending pair snapshots the consented public profile details; participant views retain that request-time information and do not reveal later hidden profile changes. Missing and nonparticipant pair IDs yield indistinguishable errors. No messages, emails or notifications are sent outside Namma Civic.

The static Vercel demo persists browser-local requests against explicitly fictional profiles. Incoming example requests can be accepted/declined; outgoing requests stay pending until a simulated peer acts, with no fabricated remote receipt. No real request is sent. Real connections require the configured backend/Firebase identity. Existing citizen auth/ward isolation and creator privacy protections remain intact.

No dependencies or cloud deployment. Additive shared contracts/routes and private collection names are approved by the orchestrator for this feature; no Firestore security-rule changes are required because unmatched collections are denied. Do not alter civic status, quorum or ledger metrics. Browser-service denial persists; automated/source checks do not establish rendered QA.
