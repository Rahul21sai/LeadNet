# Community feature setup

## Local demonstration

Run the existing development commands with `VITE_DEMO_MODE=1`. The home screen is now the community feed. Camera, manual location, nearby filtering, device posts, bookmarks, reactions and discussion can be explored locally. Device media is stored in IndexedDB. Device activity is not published, sent to representatives or counted in the civic outcome ledger.

The existing spatial landing page remains at `/city`, and the civic explorer at `/map`. The local API serves verified representative contacts and capability flags without Google Cloud credentials. These two public reads are the only API requests permitted by the offline demo client.

Camera/microphone/geolocation require a browser secure context and user permission. Localhost/127.0.0.1 qualify in supported browsers; use HTTPS on a deployed site. An uploaded image is not assigned a capture location automatically. Camera capture records device position, accuracy and time near the shutter action. The location remains reviewable and does not prove a photograph's provenance.

## Connected publication and AI

Use the existing Firebase/Cloud Run configuration in `DEPLOYMENT.md`; this task does not provision or deploy it. Set `VITE_DEMO_MODE=0` in the web environment and configure the Firebase web app. The API uses `GOOGLE_CLOUD_PROJECT`, `STORAGE_BUCKET`, `VERTEX_LOCATION` and its attached service identity or local ADC. Set `AI_MOCK=0` for live Gemini. `MODEL_COMPOSE` selects the composition model; no `GEMINI_API_KEY` is used.

Deploy the reviewed Firestore/Storage rules with the application. Browsers read public posts/comments but never write directly. Author UIDs, unrounded coordinates, idempotency state and outbox records remain private. Photos are re-encoded before publication; voice clips are never attached to posts. Social reactions and comments do not change issue verification or ledger outcomes.

With live Gemini, the composer can process a photo, text and/or a private voice note. Transcription and rewritten wording are shown for editing. A model failure preserves supplied text and identifies the fallback; audio-only failure requests a manual transcript. Cross-language wording still requires the citizen's review. Verifiers constrain numeric detail and explicit intent; they are not a guarantee of semantic equivalence.

## Official contacts

`apps/api/data/representatives.json` and its public mirror contain a dated directory of 28 MLAs and five MPs. See `research/representatives.md` for primary sources and per-record page citations. Names and email addresses are taken from official published directories, not generated by a model. Mailbox deliverability has not been tested.

Matching uses the bundled ward's assembly attribution and ECI assembly-to-parliamentary mapping. It is not an exact constituency polygon overlay. The interface shows this method and requires recipient review. Existing posts use their stored ward ID to avoid a second assignment from rounded public coordinates; email authorization uses the author's private original location.

## Direct email

Set only in ignored `apps/api/.env` or your server's secret/environment configuration:

```dotenv
RESEND_API_KEY=your_server_side_resend_key
EMAIL_FROM=LeadNet <issues@your-verified-domain.example>
PUBLIC_APP_URL=https://your-actual-deployed-app.example
```

The sending domain must be verified with Resend. The API chooses a source-backed recipient matched to the author's post, attaches the sanitized photo, enforces limits and uses a private idempotent outbox. The final send action requires the reviewed recipient, subject, body, photo and location to be confirmed. Fictional/device-only posts cannot send real representative emails. A provider receipt confirms acceptance of a delivery request, not receipt by the representative or a promise of action.

Without mail configuration, sending stays disabled; reviewed drafts remain available. A mailto draft cannot attach a photo automatically. No email was sent during implementation or tests.

## X sharing

The app opens an X/Twitter intent with reviewed text and a real public post link when available. The user completes publication on X. No X API credentials are required for this handoff. Photos and videos are not attached automatically; the user can open the media and attach it in X. Local/device and fictional examples do not get a fabricated public URL. No X post was published during implementation.

## Video runtime

The optional server adapter validates the container, transcodes to WebM, removes metadata and limits videos to 30 seconds and 20 MB. It accepts only byte-pipe input with restricted decoder protocols, bounds processing/output, and cleans temporary files. `FFMPEG_PATH` selects an existing trusted executable. Restart the API after changing its configuration.

The owner approved adding FFmpeg to Docker on 18 October 2026. The runtime layer now includes the following, before `USER node`, with `FFMPEG_PATH=/usr/bin/ffmpeg`:

```dockerfile
RUN apt-get update \
 && apt-get install -y --no-install-recommends ffmpeg \
 && rm -rf /var/lib/apt/lists/*
```

No image is deployed by this change. FFmpeg is still not installed on this Windows host, so its local API reports connected video processing unavailable. Device-only video previews remain private on the user's device. Build the approved Docker image (or configure an existing trusted executable) to enable server transcoding. Actual encoding and metadata removal must be verified against that runtime before release.

## Typography and verification limits

Anthropic's current site declares custom Anthropic Sans/Serif/Mono fonts. A reuse license was not verified, so no font binaries were downloaded or redistributed. LeadNet uses an inspired serif treatment with Georgia and the existing Inter/Kannada fonts; locally installed Anthropic families can resolve first. Licensed font files can be added separately with their license.

The browser service still denies automated access to the preview despite the owner's Allow setting. Unit/source checks do not replace rendered mobile/desktop, light/dark, actual camera/microphone/GPS or console testing. Live Gemini, mail delivery, video encoding, deployed rules and cloud persistence need their configured services and independent verification.
